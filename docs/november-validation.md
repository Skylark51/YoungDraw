# 2026년 11월 메커니즘·에너지 그래프 검증

## 작업 전 상태

C++17/Win32 구현에 이미 분기·합류·촉매 순환, 단계 삽입·삭제, 원본 위치 유지,
네이티브/CDXML 스마트 메타데이터 및 Office OLE 왕복 저장이 있다.
전체 재작성 대신 실제 가져오기 및 배치 오류를 보완했다.

## 수정

- CDXML의 꼬리 쪽 화살촉만 지정된 직선·곡선은 제어점을 역순으로 바꿔 방향과
  편집 가능한 화살촉을 보존한다. 곡선 속성의 두 가지 대소문자 표기도 처리한다.
- 실제 ChemDraw 파일에서 반복된 `objecttag` ID 때문에 도면 전체를 거부하던
  문제를 수정했다. 이 메타데이터는 원문에 보존하며 캔버스 객체로 만들지 않는다.
  도형 자체의 중복 ID 검증은 유지한다. 내보내기에서도 메타데이터 ID를 도형 ID로
  오인하여 덮어쓰지 않는다.
- 긴 에너지 그래프 범례는 글자 외에 선 견본과 간격까지 포함해 가로 폭을 계산한다.

`objecttag`의 역할은 [ChemDraw SDK의 Object Tag 설명](https://iupac.github.io/IUPAC-FAIRSpec/cdx_sdk/ObjectTag.htm)을 참고했다.
반복 ID 허용은 실제 로컬 ChemDraw 자료에 근거한 호환성 처리다.

## 재현

`build.ps1`은 기본으로 Release 빌드와 창을 만들지 않는 CTest 9개를 실행한다.
전체 UI 테스트는 로컬에서 반복 실행하지 않는다. `november_complex_graphs`는
9개 상태, 3~7개 경로, 수동 축 범위, 결측 에너지, 양방향 분기, 출판용 정돈의
5종 그래프를 SVG/CDXML/네이티브 파일로 출력하고 편집 원본 왕복 일치를 검사한다.

실제 자료 검증은 빌드 폴더에서 다음과 같이 실행한다.

```powershell
./november_validation.exe '<ChemDraw CDXML 자료 폴더>'
```

원본은 읽기만 한다. 서식 변경·저장·재열기, 원자 좌표 보존, 메커니즘 변환,
분기 추가·저장·제거를 검사한다. 변환 불가 자료는 별도로 기록하고,
변환 가능 자료 20개 또는 자료 폴더 끝까지 검사한다. 연구 원본과 임시 출력은 커밋하지 않는다.

## 한계와 후속 검증

- 네이티브/CDXML 왕복 일치는 YoungDraw 편집 데이터의 보존을 확인한다.
  ChemDraw에서 직접 다시 열어 모든 서식을 대조한 검증과는 다르다.
- Office CTest는 OLE 데이터 저장·복원 회귀 검사다. 실제 PowerPoint에서
  붙여넣기·슬라이드 저장·재열기·더블클릭 편집은 별도의 통합 검증이 필요하다.
- SVG 검토는 자동 출력과 화면 렌더링을 확인하며 학술지 게재 적합성을 보장하지 않는다.
- 일부 가져오기 경고 및 변환 불가 자료는 계속 추적해야 한다. 12월에는
  지원되지 않는 ChemDraw 도형·다중 페이지·양끝 화살촉과 실제 Office 흐름을 우선 검증한다.

## 실행 결과

- 전체 CTest: 18/18 통과. 이후 사용자 요청에 따라 UI 테스트 반복 실행을 중단했다.
- 창을 만들지 않는 CTest: 9/9 통과.
- 실제 ChemDraw 연구 파일 26개: 가져오기·선 굵기 수정·CDXML 및 네이티브 왕복 검사 통과.
  19개는 메커니즘 변환 후 분기 추가·저장·제거 및 원자 위치 보존을 통과했다.
  7개는 구조 수 또는 화살표 연결 조건 때문에 변환 불가로 별도 기록했다.
- 다중 경로 그래프 5종 SVG/CDXML/네이티브 출력 검사 통과.
  SVG 1종은 숨겨진 headless 렌더링으로 화면 배치도 확인했다.
- 일부 원본은 미지원 도형 경고가 남아 있다. 따라서 이번 결과만으로
  모든 ChemDraw 메커니즘 및 실제 PowerPoint 재편집이 완성됐다고 판단하지 않는다.

## 외부 편집용 화살표 저장 보완

일반 화살표를 저장할 때 선과 삼각형 도형으로 분리하던 동작을 수정했다.
직선·양방향 화살표는 표준 `arrow`, 곡선은 화살촉 속성을 가진 `curve`로 기록한다.
반응 단계 등 외부 참조에 쓰이는 일반 화살표 ID도 유지한다.
직선 화살표의 두 가지 속성 대소문자, 양끝 Full 화살촉 및 점선 가져오기를 보완했다.

회귀 검사는 새 도면과 가져온 도면 각각의 직선·곡선·양방향 화살표에 대해
YoungDraw.State 메타데이터를 실제로 제거한 뒤 다시 가져온다.
화살표 ID·종류·색·선 굵기·점선·양끝 위치가 유지되는지 검사한다.
실제 자료 검사에도 메타데이터 제거 후 일반 화살표 ID와 화살촉 보존 검사를 추가했다.

외부 데이터 검사 중 이전 저장 자료의 반응 스킴/단계 ID가 편집 객체 또는 그룹 ID와
겹치는 사례도 발견했다. 내보내기 전에 원본과 모델의 전체 ID 범위를 예약하고,
충돌하는 보존 스킴/단계 컨테이너에 새 ID를 배정한다. 원자·결합·화살표 ID와
ReactionStep의 구조/화살표 참조는 그대로 유지한다. 그룹 ID와의 충돌도 회귀 검사한다.
검증 자료에는 ChemDraw에서 시작해 YoungDraw로 재저장된 연구 파일도 포함된다.

## 창 없는 Office 파일 왕복 검증

`office_storage_roundtrip` 콘솔 CTest를 추가해 기본 백그라운드 빌드에 포함했다.
메커니즘 단독 1종과 3~8개 경로의 그래프 5종을 실제 OLE 복합 파일과 EMF로 저장한다.
다섯 그래프는 수동 축 범위·결측 데이터·양방향 분기·출판용 정돈을 포함한다.
저장 파일을 닫고 다시 열어 다음 항목을 검사한다.

- `YoungDrawDocument` 스트림의 원본 데이터 전체 일치
- 저장된 개체 CLSID 및 표준 OLE 표시 캐시를 통한 EMF 획득
- EMF의 표시 범위와 레코드 존재
- 재개방한 메커니즘의 분기 추가 및 에너지 값 수정 후 재저장·재개방 데이터 전체 일치

이 테스트는 프로그램 창 생성, OLE 서버 등록, PowerPoint 실행, 클립보드 사용 없이 수행한다.
실제 PowerPoint 앱의 붙여넣기·슬라이드 저장·재개방 UI 흐름을 검증한 결과로 간주하지 않는다.

## 밀집 에너지 값의 가독성 보완

수동 축 범위 -8~32, 7개 상태, 5개 경로가 0.3 간격으로 모인 그래프에서
에너지 글자가 지나치게 작아지는 현상을 회귀 테스트로 재현했다.
축 하한 근처에서 값을 위로 쌓을 때 마지막 글자 한 칸의 이동 여유가 누락돼
배치 실패로 판단하던 계산을 수정했다. 글자를 축소하기 전에 연결선 위의
흰 배경 배치도 검토하며, 준위와 표식은 계속 피한다.

수정 전 새 테스트의 가독성 검사가 실패했고 수정 후 전체 백그라운드 CTest
10개가 통과했다. 값 35개가 모두 표시되고 8.5 pt 이상이며 서로 겹치지 않는지
검사한다. 같은 그래프의 실제 Office EMF 출력도 창 없이 렌더링하여
작던 값 글자가 다른 글자와 균형 있게 표시되는 것을 확인했다.
데이터와 수동 축 범위는 변경하지 않는다.

## 양끝 화살촉 곡선 보존

CDXML 곡선과 원호의 양끝 Full 화살촉을 인식하도록 보완했다.
기존 양방향 화살표 렌더러가 양끝을 잇는 직선으로 곡선을 바꾸던 문제를 수정했다.
베지어 경로의 양끝을 각각 잘라 화살촉을 붙이며, 화살촉이 곡선 길이를 지나치게
차지하지 않도록 제한한다. CDXML도 양끝 화살촉을 가진 곡선 객체로 저장한다.
메타데이터 없는 재가져오기에서 양끝 위치·곡선 제어점·양방향 종류를 검사한다.

백그라운드 CTest 10/10, 기존 연구 파일 26개 검사도 통과했다.

## 실제 PowerPoint 백그라운드 저장 검증

설치된 PowerPoint에서 `Presentations.Add(0)` 및 `Presentations.Open(...,0)`으로
문서 창을 만들지 않고 6개 슬라이드의 저장·재개방·재저장을 실행했다.
PowerPoint가 만든 EMF 슬라이드에 기존 OLE 원본을 Open XML 개체로 연결하고,
실제 PowerPoint에서 다시 저장한 PPTX의 6개 `YoungDrawDocument` 스트림 SHA-256이
입력 원본들과 일치하는지 확인했다. OLE 표시 캐시와 EMF 미리보기도 남아 있다.
검증 산출물은 `build/powerpoint-background`에 둔다.

재현: 먼저 빌드의 `office_storage_roundtrip`을 실행해 자료를 생성하고 다음을 실행한다.
Python의 `olefile` 패키지와 Windows PowerPoint가 필요하다.

```powershell
./tools/test-powerpoint-background.ps1 -Stage Prepare
python tools/verify-powerpoint-package.py prepare
./tools/test-powerpoint-background.ps1 -Stage Reopen
python tools/verify-powerpoint-package.py
```

이미 실행 중인 PowerPoint가 있으면 기본적으로 중단하여 사용자 세션을 보호한다.
시험 프로세스 재사용 옵션은 해당 프로세스의 문서와 창이 모두 없는지도 검사한다.

검증 범위는 실제 PowerPoint 저장 후 원본·벡터 표시의 보존이다.
창 없는 문서에서는 PowerPoint OLE 붙여넣기가 거부되어 통과로 집계하지 않았다.
직접 OLE 파일 삽입도 지원되지 않았다. 더블클릭 편집은 창을 표시하므로 이번
백그라운드 검사에는 포함하지 않았다. 최종 스크립트는 클립보드를 사용하지 않는다.

## OLE 재편집 명령·호스트 저장 검증

복사와 파일 내보내기가 같은 `createDataObject` 경로를 사용하도록 정리했다.
창 없는 테스트 호스트는 실제 `IOleObject`의 PRIMARY/OPEN 명령, 편집 콜백,
`office::update`, `IOleClientSite::SaveObject`, `IPersistStorage::Save` 및
SAVEIFDIRTY/NOSAVE 닫기 명령을 호출한다. 표시 창이 없는 호스트에서는
창 표시와 포커스 요청을 생략한다.

메커니즘 및 그래프 5종 모두에서 원본 열기, 수정 저장, 저장 후 다시 열기,
미저장 수정 취소, 닫을 때 저장하기를 검사한다. 호스트가 받은 저장소의 원본과
표시 캐시까지 다시 읽어 비교한다. 클립보드는 건드리지 않는다.
전체 백그라운드 CTest 10개가 통과했다.

혼합 화살촉 서식의 확대 검증이며, 현재 미검증된 Office 흐름은 별도로 유지한다.
